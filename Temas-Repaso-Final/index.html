Tema 1

Unidades de Longitud: px vs rem vs em

Las unidades relativas (rem y em) son fundamentales para la accesibilidad. Permiten que el usuario ajuste el tamaño de fuente global y todo escale proporcionalmente.

📍 🔑 LA DIFERENCIA FUNDAMENTAL:

⭐ REM = "Root" (RAÍZ)

SIEMPRE pregunta: ¿Cuál es el tamaño del <html>?

<html> = 16px
↓ (REM siempre mira aquí)
.card { 1.2rem }
↓
.button { 1rem }

✅ 1rem = 16px
✅ 1.2rem = 19.2px
✅ No importa dónde esté el elemento

🎯 EM = "Element" (PADRE)

SIEMPRE pregunta: ¿Cuál es el tamaño de mi PADRE?

<html> = 16px
↓
.card { 1.2rem = 19.2px }
(padre de button)
↓
.button { 1em = 19.2px }
(1em aquí = padre 19.2px)

⚠️ 1em = padre
⚠️ 1em en button = 19.2px
⚠️ Depende del contexto

Media Queries: Ejercicio Responsive

Las media queries permiten adaptar el diseño a diferentes tamaños de pantalla. El enfoque mobile-first (usar min-width) es más mantenible y eficiente.

Breakpoints típicos:

  • Mobile: 0 – 767px
  • Tablet: 768px – 1023px
  • Desktop: 1024px+

Mobile (<768px): 1 columna · Tablet (768–1023px): 2 columnas · Desktop (≥1024px): 3 columnas 
/* Mobile First */
.column { width: 100%; }

@media (min-width: 768px) {
  .column { width: 50%; }
}

@media (min-width: 1024px) {
  .column { width: 33.333%; }
}
Tema 3

Flexbox: Propiedades del Contenedor

Flexbox es el layout 1D más especificado. Controla cómo se distribuyen los ítems en una dimensión (fila o columna) y cómo se alinean.

Propiedades clave del contenedor:

  • display: flex → activa el modelo flexible.
  • flex-direction → dirección del eje principal (row, column).
  • justify-content → alineación en el eje principal.
  • align-items → alineación en el eje cruzado.
  • flex-wrap → salto de línea cuando no hay espacio.
  • gap → espacio entre ítems.

.container {
  display: flex;
  flex-direction: row;
  justify-content: flex-start;
  align-items: center;
  flex-wrap: nowrap;
  gap: 10px;
}
Tema 4

CSS Grid: Introducción

CSS Grid es el layout 2D más potente. Controla ambas dimensiones (filas y columnas) simultáneamente, ideal para layouts complejos.

Propiedades clave:

  • display: grid → activa el modelo grid.
  • grid-template-columns → define columnas (200px, 1fr, auto, etc.).
  • grid-template-rows → define filas.
  • gap → espacio entre filas y columnas.
  • grid-auto-flow → cómo se colocan los ítems (row o column).

.container {
  display: grid;
  grid-template-columns: 1fr 1fr 1fr;
  gap: 10px;
}

   - Flexbox: layout 1D (fila O columna)
   - Grid: layout 2D (fila Y columna) */
Tema 5

Grid + Media Queries: Layout Adaptativo

Combinar Grid con media queries permite layouts sofisticados que se adapten a cualquier dispositivo, manteniendo el orden del contenido.

Ejemplo: diseño de gimnasio

  • Mobile: 1 columna (header, nav, main, footer apilados).
  • Tablet: 2 columnas (nav lateral + contenido).
  • Desktop: Header a todo ancho, nav+main en paralelo, footer a todo ancho.

/* Mobile-first */
.layout {
  display: grid;
  grid-template-columns: 1fr;
  gap: 1rem;
}

/* Tablet */
@media (min-width: 768px) {
  .layout {
    grid-template-columns: 200px 1fr;
  }
  .layout-header { grid-column: 1/-1; }
  .layout-footer { grid-column: 1/-1; }
}

/* Desktop */
@media (min-width: 1024px) {
  .layout {
    grid-template-columns: 200px 1fr;
    grid-template-rows: 60px 1fr 60px;
  }
}
Tema 9-10

Accesibilidad: Estructura Semántica & ARIA

La accesibilidad es crucial para que todo el mundo pueda usar tu web. Usa etiquetas semánticas (<header>, <nav>, <main>, <footer>, <article>) y atributos ARIA cuando sea necesario.

Checklist de accesibilidad:

  • ✅ Usa etiquetas semánticas: <header>, <nav>, <main>, <article>.
  • ✅ Todo formulario debe tener <label> asociada con for o anidada.
  • ✅ Imágenes requieren alt descripción.
  • ✅ Contraste de color: mínimo 4.5:1 para texto normal.
  • ✅ Usa unidades relativas (rem): permite que usuarios amplíen texto.
  • ✅ ARIA (role, aria-label, aria-hidden) solo cuando la semántica HTML no es suficiente.
  • ✅ Testea con lectores de pantalla (NVDA, JAWS, VoiceOver).

📌 Atributos de accesibilidad en formularios:

for + id

Vincula label con input. Lectores leen la label al enfocar input.

aria-required="true"

Indica a lectores que campo es obligatorio (complementa required).

aria-describedby

Vincula texto de ayuda al input. Lectores lo leen después del label.

<fieldset> + <legend>

Agrupa checkbox/radio y describe el grupo. Essential para accesibilidad.

aria-label

Describe elementos sin etiqueta visible. Ej: formulario, botones icon.

type="date"

Nativo HTML semántico. Mobile y lectores lo entienden mejor que input text.

Ejemplo accesible: Formulario de Reserva

Escribe tu nombre y apellido
¿Necesitas equipo? (opcional)

✅ Elementos accesibles utilizados:

<label for> + <input id>

Vincula la etiqueta con el input. Cuando usas un lector de pantalla, al enfocar el input, escuchas la label.

aria-required="true"

Comunica a los lectores de pantalla que el campo es obligatorio. Complementa el atributo required.

aria-describedby

Vincula texto de ayuda al input. El lector lee la label, luego el texto de ayuda, para mayor claridad.

<fieldset> + <legend>

Agrupa checkbox o radio buttons. La leyenda describe el grupo. Essential para accesibilidad con múltiples opciones.

aria-label="..." en form

Describe el propósito del formulario. Útil cuando no hay texto visible que lo describa.

type="date"

Tipo semántico nativo. Móviles muestran datepicker, lectores lo entienden mejor que input text.
