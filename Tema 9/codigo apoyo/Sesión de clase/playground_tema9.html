01

Fundamentos de SEO técnico

El SEO técnico garantiza que una aplicación pueda ser descubierta, rastreada, renderizada, comprendida e indexada de forma fiable. No es marketing: es ingeniería de plataforma.

📮Analogía del cartero. Imagina un cartero (el bot) que reparte a una ciudad enorme. Necesita direcciones reales (URLs en enlaces <a>), un mapa (sitemap), señales de tráfico (robots.txt) y buzones que respondan (códigos HTTP). Si la casa solo aparece tras "encender la luz" (ejecutar JavaScript), muchos carteros se van sin entregar.

// app/sitemap.js
export default async function sitemap() {
  const posts = await getPosts();
  return [
    { url: 'https://tienda.com', lastModified: new Date() },
    ...posts.map(p => ({
      url: `https://tienda.com/blog/${p.slug}`,
      lastModified: p.updatedAt,
    })),
  ];
}

Metadata, Open Graph y gestión del <head>

En App Router el <head> es declarativo y ligado a la ruta. Nada de next/head: se usa metadata (estática) o generateMetadata (dinámica), y se resuelve en servidor.

🪪Analogía del DNI del documento. La metadata es el carné de identidad de cada página: su nombre (title), su descripción y su foto para compartir (og:image). Si el carné se rellena "tarde" (en cliente), el portero que no espera —un bot o un previsualizador— se queda sin saber quién eres.

export async function generateMetadata({ params }) {
  const p = await getProduct(params.slug);
  return {
    title: p.name,
    alternates: { canonical: `/es/productos/${p.slug}` },
    openGraph: { images: [p.image] },

03
SEO e internacionalización

  
Con varios idiomas el reto deja de ser indexar una página y pasa a indexar bien una familia de páginas equivalentes, sin que compitan entre sí (canibalización).


  

    🌍Analogía de la edición de un libro. Un mismo libro en español, inglés y francés son ediciones distintas, no copias piratas. hreflang es la nota "esta es la edición francesa de la misma obra"; canonical es "esta es la portada oficial de esta edición". Cada edición se firma a sí misma y señala a las demás.
  


  
Explorador hreflang ⇄ canonical

  
Elige el idioma del visitante y observa qué <head> debería emitir la página correspondiente. Fíjate en la simetría: todas declaran el mismo conjunto.

  

    

      
      
      
    

    

    

  


  
Tres cosas que separan "funciona" de "posiciona"

  

    
↔️ Simetría
Cada versión declara el mismo conjunto de alternates (ida y vuelta). Si la ES apunta a la EN pero la EN no devuelve el gesto, se rompe.

    
🎯 Precisión de códigos
Idiomas válidos y regiones con estándar (es-ES, es-MX). Lighthouse detecta errores típicos.

    
🔗 URLs absolutas
Para canonical y hreflang, apoyadas en metadataBase. Las anotaciones internacionales son sensibles a inconsistencias.

    
🈯 Metadata localizada
No basta traducir el contenido visible: title, description y OG también. Si no, el HTML "dice" una cosa y su identidad documental, otra.

El rendimiento es señal de experiencia. Google mide Core Web Vitals con datos reales de usuario. Buen rendimiento no garantiza el puesto 1, pero malo sí te penaliza.

05
Despliegue

  
Publicar no es "subir ficheros": según el render (SSR, Route Handlers, ISR) puede hacer falta infraestructura ejecutable. Vercel es el entorno gestionado más alineado con Next.js.


  

    🔑Analogía de las llaves. Una variable NEXT_PUBLIC_ es como una llave que imprimes en folletos: cualquiera la ve. Una variable privada es la llave de la caja fuerte: jamás se imprime, solo se usa dentro del banco (el servidor). Confundirlas es el fallo de despliegue más caro.
  


  
Clasifica las variables: ¿pública o secreta?

  
Arrastra mentalmente cada variable a su sitio. Pulsa para alternar el prefijo y observa la fuga.

  


  
Entornos por defecto en Vercel

  

    
🖥️ Local
Tu máquina. next dev. Variables desde .env.local.

    
🔍 Preview
Cada rama / pull request genera una URL real para validar caching, ISR, cabeceras… antes de producción.

    
🚀 Production
Dominio principal. El merge a la rama de producción promueve el despliegue.

    
⚙️ Autónomo
output: 'standalone' para Docker / AWS / Azure cuando se necesita control total.

  

  
⚠️ process.env no es un objeto normal: muchas variables se sustituyen en build-time. No las destructures; usa process.env.MI_VARIABLE de forma explícita.
