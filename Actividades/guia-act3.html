Criterio 3 · 10%

1 · Personalización de tailwind.config.js

Lo primero es definir la identidad visual de Nexus. Si usamos bg-orange-600 genérico de Tailwind, no estamos personalizando nada. Lo que hacemos es declarar colores propios y tipografías propias, de forma que cualquier cambio futuro de marca solo afecte a este archivo. 

// tailwind.config.js
module.exports = {
  theme: {
    screens: {
      xs: '420px',    // breakpoint extra para móviles grandes
      sm: '640px', md: '768px', lg: '1024px', xl: '1280px'
    },
    extend: {
      colors: {
        'nexus-cream':       '#F7F1E8',  // fondo cálido
        'nexus-dark':        '#1F1A14',  // texto y footer
        'nexus-accent':      '#C0683A',  // CTAs y precios
        'nexus-accent-dark': '#9A4E25',  // hover del accent
        'nexus-leaf':        '#3F6B4E',  // badges "vegano"
        'nexus-muted':       '#6E6357'   // texto secundario
      },
      fontFamily: {
        display: ['Fraunces', 'serif'],
        body:    ['Inter', 'sans-serif']
      },
      boxShadow: {
        soft: '0 4px 20px -8px rgba(31, 26, 20, 0.15)'
      }
    }
  }
}
💡 Por qué nombres semánticos: usar nexus-accent en lugar de orange-600 hace que el HTML sea autoexplicativo, y permite cambiar toda la paleta tocando un solo archivo.
Criterio 2 · 35%

2 · Componentes reutilizables con @apply y @layer

Tailwind es utility-first, pero cuando un patrón se repite muchas veces (por ejemplo, el botón principal aparece en 8 sitios) lo extraemos a un componente. Eso se hace en src/input.css: 

/* src/input.css */
@tailwind base;
@tailwind components;
@tailwind utilities;

@layer components {
  .btn {
    @apply inline-flex items-center justify-center gap-2
           px-4 py-2 rounded-lg font-medium transition
           focus:ring-2 focus:ring-nexus-accent;
  }
  .btn-primary  { @apply btn bg-nexus-accent text-white hover:bg-nexus-accent-dark; }
  .chip-on      { @apply chip bg-nexus-dark text-nexus-cream; }
  .chip-off     { @apply chip bg-white text-nexus-muted hover:border-nexus-accent; }
  .card-producto{ @apply bg-white rounded-2xl shadow-soft overflow-hidden
                          flex flex-col hover:shadow-xl hover:-translate-y-1
                          transition duration-300; }
}
⚖️ Regla práctica: extraigo a componente cuando uso el patrón 3 o más veces. Si lo uso 1-2 veces, lo dejo inline en el HTML. Abusar de @apply es montar CSS clásico disfrazado y rompe la filosofía de Tailwind.
Criterio 1 · Mobile-first

3 · Header sticky con menú adaptativo

El header se pega arriba al hacer scroll y usa backdrop blur para mantener legibilidad. El menú de navegación se oculta en móvil (donde sobra espacio) y aparece a partir de md: (768px).

<header class="sticky top-0 z-20 bg-nexus-cream/85 backdrop-blur
                       border-b border-nexus-paper">
  <div class="container mx-auto px-4 sm:px-6 lg:px-8 py-3
                    flex items-center justify-between gap-4">
    ...
    <!-- Solo visible desde tablet -->
    <nav class="hidden md:flex items-center gap-6"> ... </nav>
    ...
  </div>
</header>
  • sticky top-0 z-20 → se ancla arriba al hacer scroll
  • bg-nexus-cream/85 backdrop-blur → fondo semitransparente con desenfoque
  • hidden md:flex → el patrón mobile-first por excelencia: oculto por defecto, visible desde tablet

Criterio 2 · Componentes

5 · Filtros con scroll horizontal en móvil

En móvil no caben 7 categorías en una fila, así que en lugar de apilarlas verticalmente (que ocuparía mucho alto) hacemos que el contenedor pueda desbordarse y desplazarse horizontalmente. Cada chip está construido con el componente .chip-on / .chip-off definido en input.css.

<div class="flex items-center gap-2 overflow-x-auto pb-1">
  <span class="chip-on">Todos</span>
  <span class="chip-off">☕ Cafés</span>
  <span class="chip-off">🍵 Tés & infusiones</span>
  ...
</div>
🎯 Fíjate en lo limpio que queda el HTML al usar chip-on en lugar de las 8 utilidades que esa clase encapsula. Eso es lo que evalúa el criterio 2.

Criterio 1 · CSS Grid responsive

6 · Cuadrícula de productos progresiva

El número de columnas cambia según el viewport. Una sola declaración con prefijos responsive lo controla todo:

<div class="grid grid-cols-1 xs:grid-cols-2
                    lg:grid-cols-2 xl:grid-cols-3 gap-5">
  <!-- 6 cards de producto -->
</div>
  • 📱 Móvil pequeño (< 420px): 1 columna
  • 📱 Móvil grande (≥ 420px): 2 columnas
  • 💻 Desktop (≥ 1024px): 2 columnas + columna lateral del resumen
  • 🖥️ Desktop ancho (≥ 1280px): 3 columnas + columna lateral
🔍 Para la videomemoria: abrid DevTools (F12) y redimensionad la ventana en vivo mientras explicáis. Es la forma más visual de demostrar el comportamiento responsive.
Criterio 1 · Flexbox Criterio 2 · Componente

7 · Anatomía de una card de producto

Cada card es flex flex-col para que el botón quede siempre pegado abajo aunque las descripciones tengan distinto largo. El flex-1 en la descripción es el truco que empuja al botón.

<article class="card-producto">
  <div class="aspect-[4/3] bg-gradient-to-br from-amber-100 to-orange-200
                  flex items-center justify-center text-6xl">☕</div>
  <div class="p-4 flex flex-col gap-2 flex-1">
    <div class="flex items-start justify-between gap-2">
      <h3 class="font-display font-semibold text-lg">Flat white</h3>
      <span class="font-bold text-nexus-accent">2,90 €</span>
    </div>
    <p class="text-sm text-nexus-muted flex-1">Doble ristretto...</p>
    <span class="badge bg-nexus-leaf/10 text-nexus-leaf">Sin lactosa ✓</span>
    <button class="btn-primary w-full mt-3">Añadir</button>
  </div>
</article>
  • aspect-[4/3] → ratio fijo, las imágenes siempre tienen la misma proporción
  • flex-1 en el <p> → empuja al botón hasta el fondo
  • nexus-leaf/10 → fondo verde al 10% de opacidad (sintaxis moderna de Tailwind)
  • aria-label, alt, <button> real → accesibilidad sumando puntos al criterio 1

Criterio 1 · Grid avanzado

8 · Columna lateral sticky en desktop, debajo en móvil

El layout principal usa una grilla de 2 columnas solo en desktop. En móvil y tablet, todo va apilado verticalmente. Además, la columna del resumen se queda fija al hacer scroll.

<div class="grid lg:grid-cols-[1fr_320px] gap-8">
  <section> ... productos ... </section>
  <aside class="lg:sticky lg:top-32 lg:self-start">
    ... resumen del pedido ...
  </aside>
</div>
  • lg:grid-cols-[1fr_320px] → grilla arbitraria: la primera columna ocupa el espacio sobrante, la segunda 320px fijos
  • lg:sticky lg:top-32 → el resumen se ancla a 128px del top al hacer scroll, pero solo desde 1024px
  • lg:self-start → evita que la columna se estire al alto de la otra
💡 Esta sección cubre también la opción 3 del enunciado (pantalla de resumen de pedido). Sin necesidad de hacer una página aparte, integramos el resumen como columna lateral.

10 · Estructura del ZIP final

Recordad: este archivo es didáctico. En vuestra entrega no hay paneles oscuros ni CDN. Tenéis que separar los archivos así:

DWR-ACT3-ApellidoNombre.zip
├── videomemoria.mp4
└── proyecto/
    ├── index.html              // limpio, sin paneles de explicación
    ├── tailwind.config.js      // el bloque que aquí está en <script>
    ├── package.json
    ├── src/
    │   └── input.css           // el bloque que aquí está en <style>
    └── dist/
        └── output.css          // generado por: npm run build
  • ❌ SIN node_modules/ (lo dice expresamente el enunciado).
  • ✅ Compilad antes de entregar: npx tailwindcss -i ./src/input.css -o ./dist/output.css --minify
  • ✅ Cambiad el <script src="https://cdn.tailwindcss.com"> por <link rel="stylesheet" href="./dist/output.css">
  • ✅ Registrad la actividad en el formulario de Moodle (aunque sea individual).
